# Prescribed controller provenance

The source-to-destination manifest identifies the archived final paper refresh that supplies `evaluation/trajectories.py`. Its resource rollout calls `_resource_rates`, which calls the allocation helper copied into `economics/load_accounting.py`. The power-only trajectory replay and training objective call the same allocation helper. The standalone resource-support wrapper was copied into `anchors/controller.py`; the environment's physical-metric path is in `restoration/environment.py`.

The final trajectory helper sorts eligible disconnected loads in descending tuple order: critical status, the fixed `voll_usd_per_kwh` field, load MW, anchor identifier, then load identifier. It allocates the pooled export cap sequentially and permits a partial final load block. The support wrapper retains this tuple ordering. The physical-metric implementation retains its original tie break using anchor capacity in place of anchor identifier. All three implementations are preserved; no tie-breaking rule has been substituted.

The release names this behavior `critical_first_fixed_priority`: **deterministic critical-first allocation with a fixed within-class priority**. The mode is explicit on the environment and in the training configuration; unknown modes fail rather than changing dispatch implicitly. `voll_usd_per_kwh` is a legacy compatibility field used for this fixed ranking and auxiliary accounting. It is not the paper's economic interruption-damage objective. Likewise, `greedy_voll_edge_id` is an inherited training-state schema field, not the name of the current Greedy objective.

The SI's support-allocation description refers to critical status and economic interruption-damage consequence. The archived trajectory implementation does not rank support recipients by the load-level duration-dependent damage function. That function depends on accumulated unserved energy; choosing a marginal interval, a full-block versus per-unit score, or the next repair duration would specify a new dispatch rule. The supplied descriptions do not select among these choices. This release therefore does not invent or expose an economic-priority dispatch mode.

Repair-candidate screening, lookahead labels, learning rewards and deployment damage continue to use the source-based interruption-damage implementation. Distinguishing that repair objective from the fixed support allocation preserves the final implementation's behavior and makes the documentation precise.

The default controller has not changed. Research-scale restoration and anchor trajectories have not been rerun and are not claimed to have been reproduced. A future change in support priority would require evaluating the frozen policies under the new controller and regenerating affected trajectory and anchor comparisons. The external SI wording should be reconciled with this trace before publication.
